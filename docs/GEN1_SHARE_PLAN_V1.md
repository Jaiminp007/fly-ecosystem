## Why alert (location-sharing is impossible frozen; aggregation hurts)
Frozen controllers navigate only by in-range cue taxis + motor
primitives — they cannot use out-of-range locations (no machinery for
it), so true location-broadcast is unimplementable without changing
behavior (forbidden: naive must stay naive). Aggregation (mate-
attraction coupling) would concentrate mouths on found patches
(more competition per find — hurts the UNDER tail, not helps). The
implementable, tail-targeted, frozen-compatible sharing rule is
ALERT: the FACT of discovery (not the location) is shared — any
substantial meal extends every agent's sensor range, so all search
wider and find more (more total intake → covers costs → lifts UNDER).
- STATED RULE (one): "In each tick, if any alive agent's intake
  (lastFood) exceeds E=0.2 (a substantial meal, ~7× typical), every
  alive agent's sensor range (genome.traits.sense) is set to 2× its
  placement baseline for the next 32 ticks (sliding — each new event
  extends the window); otherwise baselines are restored." Frozen
  taxis/motor untouched (only sensor range — a plain genome field,
  like energy placement); no learning (acquisition stays off);
  sensing is passive (no direct cost). Discovery events and alert
  ticks engaged are metered (rule-fired proof).
- Arms (3 × 2 histories = 6 mains): SHARED (fresh-clean-24 + alert
  rule) vs ASOCIAL (fresh-clean-24, no alert — identical except the
