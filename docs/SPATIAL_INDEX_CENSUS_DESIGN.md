# Exact spatial-index opportunity census

Before changing the paid controller, measure its actual local point and pair
workload on the already captured replay-arm C acquisition and current transfer
segments from all eight reused histories. Restore the captured-source start,
replay each segment without changing controller decisions or prices, and check
its complete final checkpoint against the previously captured end. Inspect
the controller's own already constructed point list, without giving any new
signal or labels to the body. Recompute each strict-tie midpoint recommendation
and verify it against the observed event.

For a hypothetical one-dimensional 32-unit cell index, count original pairs,
pairs in the same or adjacent cells, and actual pairs with forward separation
at most 32. Explicitly check that every pair the existing filter reaches is
contained in those cells, including negative coordinates and boundary cases.
The difference between original and neighboring-cell pair counts gives only
the maximum number of existing three-operation pair checks that this index
could skip before paying any index construction, traversal, sorting, memory or
storage costs. It is not a measured net saving or physical performance claim.

If the gross headroom is material, a prospective implementation must preserve
the original first/second iteration order and strict ties exactly, account for
all index construction and dynamically retained bytes, and pass synthetic
boundaries/duplicates plus independent physical equivalence tests before
performance testing. Do not tune the score, gate or action policy. This census
uses reused development evidence, not fresh qualification or RSI.
