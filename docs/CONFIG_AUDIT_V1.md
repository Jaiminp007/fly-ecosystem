# CONFIG AUDIT V1: the sterile control was bar, not luck (and levels were enrichment, not topology)

Analytic-only. Zero new worlds, zero new seeds, zero bank draws.
Reads frozen mate-*/rows configs (mode, decoupled, bar, topology,
nutrientOverride) x births across all lines.
Question: why did MATE-WINDOW control (hub, bar-65, legacy)
birth 0/6 while prior hubs birthed 5–9?

## Findings

1. **The birthy base was enriched, not just hub.** Every prior
   birthy hub arm (attract/encounter/leave/proximity/recombine,
   meds 4–9) ran nutrientOverride=5 (constant enrichment) at
   bar-50. Every birthy spread arm likewise (5.0, bar-50).
   V1 plan's "hub base (birthy 5–9)" misattributed enrichment
   levels to topology. CORRECTION published as such.
2. **The ENCOUNTER contrast is exonerated.** Hub-vs-spread
   comparisons WITHIN lines shared nutrients (both 5.0) —
   topology effects (hub 5 vs spread 3, GO) are internally
   valid. Only absolute LEVELS were enrichment-inflated.
   No verdict rescored (contrasts intact, levels re-labeled).
3. **Sterility pattern = bar-65 + legacy (2/2), not luck.**
   bar-65+legacy+spread (ENERGY): 0/6. bar-65+legacy+hub
   (WINDOW): 0/6. bar-50+legacy+spread (FOOD): med 2.0,
   all seeds birthy. bar-50+enriched+hub: 5–9. The bar
   dominates; topology secondary; bank luck cannot explain
   0/6 + 0/6 across two topologies (two independent sterile
   banks far less likely than the shared bar).
4. **V1 held the wrong default.** "Bar HELD at 65 (V1 default)"
   was never birthy with legacy nutrients anywhere (untested
   combination presented as safe base). The error is config,
   not chance — which makes it fixable by config (V2), not
   by re-drawing banks (luck).
