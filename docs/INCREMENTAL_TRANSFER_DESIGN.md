# Indexed transfer: fixed physical comparison

The incremental index showed a small declared same-state cost reduction on
reused trajectories. Test whether it changes outcomes in the physical world,
without claiming that an engineered index is an acquired skill. Use the eight
already recorded replay-steering D checkpoints and their existing separate
transfer probe seeds; do not open any reserve. No refill, revival, new training
or counterfactual labels are permitted. Preserve source and input hashes,
starting worlds, full traces, endpoints, survivors and all inherited debt.

From each identical D physical state, compare frozen learned steering with
the original filtered selector and with the incremental selector. Also run
incremental reset and incremental forced-native controls, and cheap native-full
from the same start. Incremental arms pay all index work and retained bytes;
all model, motor and taste states otherwise come from the same individual D
checkpoint. Original and incremental learned arms begin with the same frozen
model weights and setup debt. Different paid costs can change physical energy,
guard decisions, food competition, RNG trajectories and mortality.

The selector-only contrast is descriptive. For the unchanged exploratory
transfer gate, incremental learned must have positive mean budget energy,
at least 6/8 positive histories and nonnegative aggregate survivor difference
against both incremental reset and cheap native-full. A pass would still be
outcome-informed development evidence only; A/B retention, functional pressure,
fresh qualification and later autonomous revision remain separately required.
Independently check trace hashes, same starting worlds, frozen models, reported
work/storage/debt and physical receipts. Captured-source replay is not an
independent physical simulation or complete low-level operation audit.
