# Active implementation and exploratory development goal

On 2026-10-25 the user explicitly requested a new immediate goal: substantial
implementation chunks, brief checks, then diagnose/fix/retry on failure, with
much less verification overhead. The native goal is now a working embodied
learner with reproducible **development-stage** energy gains over frozen/reset
controls and honest survival/cost reporting, with a one-hour checkpoint.

This instruction supersedes the exhaustive-before-every-run workflow for new
exploratory development. Runs are explicitly reusable development evidence;
method changes and failures are recorded by source hash and attempt. No such
gain is fresh qualification, retained-skill proof or recursive self-improvement.
The previous locked protocols, failed results and all closed reserves remain
immutable. Rigorous fresh retention/pressure/transfer and RSI evaluation comes
after a promising integrated milestone, not after every small code edit.

The first chunk integrates the complete taste/energy learner into physical
A/B/C/return-A worlds, frozen/reset controls and matched saved-model probes.
Use a short targeted integration check, then run a small explicit development
bank and inspect actual energy, food, toxin, mortality and learned/reset gains.
Improve the measured weakness before spending on a large certification campaign.
